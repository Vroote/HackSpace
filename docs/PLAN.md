# HackSpace — Kanban и план выполнения задач

## MVP

Общий веб-сервис для одного GitHub Project организации и одного репозитория. Пять вкладок: **Задачи**, **Pull Requests**, **План задач**, **Архитектура**, **Результаты**. Карточки на доске и плане — это Issues; связанные PR остаются ссылками на карточках.

## Задачи и план

- **Задачи — Kanban.** Показывать только Issues в колонках GitHub Project, карточки без статуса — отдельно. Перетаскивание меняет `Status` в GitHub от имени участника; при отказе карточка возвращается в исходную колонку. Колонки `Done` и «Готово» снимают блокировку открытого Issue внутри проекта.
При снятии последней зависимости исполнитель видит уведомление со ссылкой на задачу. Активная вкладка сверяет доску каждые две минуты. История наблюдений и отметки о прочтении хранятся в этом браузере.

- **Pull Requests.** Показывать все PR настроенного репозитория, даже без привязки к Issue. Список загружается постранично и содержит автора, статус, решение по ревью, ветки и время обновления. Фильтр «Запрошено моё ревью» показывает личные запросы, время ожидания при наличии даты и ссылки на связанные задачи доски.
- **План задач — граф слева направо.** Показывать все открытые Issues проекта из выбранного репозитория, включая задачи в работе. Стрелка идёт от блокера к зависимой задаче. Задачи без активных предшественников внутри плана стоят в первом столбце, друг под другом; зависимая задача — правее самого правого из её предшественников. Столбцы показывают порядок зависимостей, а не даты или статусы Kanban. Позиции рассчитываются автоматически, без ручной раскладки.
- **Карточка на плане.** Номер и название Issue, статус, аватары всех назначенных исполнителей или **Без исполнителя**. Если есть PR, показывать кликабельные номера и состояния (`Черновик`, `Открыт`, `Слит`, `Закрыт`). Использовать только [нативные связи GitHub](https://docs.github.com/en/graphql/reference/issues), включая ручные привязки; не угадывать по названиям веток и не создавать отдельные карточки для PR.
- **Препятствия и обновление.** Внешние, отменённые или недоступные блокеры помечать прямо на карточке с объяснением: первый столбец не означает «можно брать». Задачи в цикле и задачи, зависящие от него, показывать в отдельной области **Порядок не определён**. Кнопка **Обновить план** перечитывает Issues, исполнителей, зависимости и PR из GitHub. DeepSeek не определяет порядок задач.
- **Стиль.** Холст в духе Obsidian Canvas: точечная сетка, компактные карточки, направленные линии, панорамирование и масштабирование. Цвета фона, рамок и статусов — в тонах GitHub. План доступен для просмотра; изменение статусов остаётся на Kanban.

## Остальные вкладки и интеграция

- **Архитектура.** Кнопка **Перестроить схему** фиксирует SHA основной ветки и запускает фоновое задание. DeepSeek получает ограниченный контекст и вызывает `render_architecture`; сервер проверяет компоненты, связи и пути, затем отображает граф. Команда видит общую схему со ссылками на файлы зафиксированного коммита. Новый коммит помечает схему устаревшей; ошибка не затирает последнюю успешную версию. Приватные файлы отправляются только после разрешения администратора и подтверждения точного списка участником. У модели нет GitHub-токена или прав на запись.
- **Результаты.** Участник вручную вносит SHA, время внешнего теста и балл `0–100`. Сервер проверяет коммит и хранит полный SHA, время в UTC, балл и автора. Ось X — время теста, ось Y — балл; SHA и ссылка на коммит доступны у точки. Повторные тесты одного коммита — отдельные замеры, все видны в истории под графиком. График и разница баллов учитывают выбранные набор и версию. Участник с правом записи может выбрать один замер для общего демо, указать ссылку на стенд и причину выбора. HackSpace не запускает тесты.
- **Реализация.** Next.js, TypeScript, PostgreSQL и один фоновый обработчик; React Flow и Dagre для графов. GitHub App без аккаунта-помощника: `Projects: write` для переноса, остальные необходимые права — на чтение. Доступ к общим данным проверяется на сервере от имени участника; добавлять замеры могут участники с правом записи в Project. При сбое GitHub последнее успешное состояние помечается устаревшим. Merge PR, запуск CI и изменение зависимостей из обёртки вне MVP.

## Приёмка

- Если задачи A и B независимы, они стоят параллельно. Если C зависит от обеих, она стоит правее с двумя входящими стрелками.
- Карточка корректно показывает ноль, одного или нескольких исполнителей и связанных PR. PR без связанной задачи не появляется на плане; изменение связи видно после обновления.
- Внешний блокер или цикл не создаёт ложное **Можно брать**. Перенос карточки отражается в GitHub; пользователь с правом чтения не может изменить статус даже через API.
- Два замера одного SHA видны отдельно; внесённый задним числом замер занимает место по времени теста. Значения вне `0–100` и неподтверждённые коммиты отклоняются.
- Новый коммит помечает архитектуру устаревшей, ошибка генерации сохраняет прошлую схему, а неодобренный приватный файл не отправляется модели.
